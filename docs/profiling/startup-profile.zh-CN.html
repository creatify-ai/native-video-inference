Cold start profile：Wan、H3 与 LTX

用当前代码真实容器的 trace，说明 Wan、H3 和 LTX 的各个组件在 cold start 中如何把权重放到 GPU 上，从第一行用户代码到第一个 DiT step。每个任务是什么，见工作分类与依赖关系。

这是 profiling，不是 benchmark：trace 会记录每次读取和拷贝，本身会多花时间，cold start 数字请以 README 的表为准。原生代码是 main 的 ad2a49a，在 Volume 跑热之后，用示例的 --cold-start 10 --trace 在 Modal us-west 全新的一次性 B200 容器上运行。

1. Trace 说明了什么

半秒内开始读，不等 CUDA。Reader 在 CUDA context 创建之前就开始读；context 就绪后开始拷贝，后面的读取和前面的拷贝重叠。

CPU 工作和 plan 都藏在读取下面。Tokenizer、图像预处理、请求结构，以及从录制 bundle 恢复的 attention plan，都在权重还在流入时完成。

组件之间重叠。H3 每个组件一个进程并行加载，LTX 五组权重同时加载，Wan 分阶段加载，让 encoder 在 DiT 流入时就构建并运行。

对象在首次使用时、权重一到就构建。三个模型的第一个 DiT step 都在最后一个所需权重字节到位后 0.1 s 内开始，剩下的就是存储带宽。

2. 每个模型如何加载

时间取自每个模型中位数的那个 trace 容器；在下方时间线里选它，可以看到每个区间。

Wan 2.1 I2V-14B 720P

  • 0.46 s 原生代码启动。0.47 s reader 开始读；CUDA context 在 0.89 s 就绪，CPU 前端（tokenizer 和图像）在 0.47–0.81 s 同时运行。
  • 1.18 s 前从 bundle 恢复好 attention plan。
  • Stage 0 的 VAE（0.5 GB）在 1.30 s 就位，1.70 s VAE 对象就绪。
  • Stage 1 的 T5 和 CLIP（13.9 GB）在 4.14 s 就位；4.14–5.60 s 构建并运行 encoder。
  • Stage 2 的 DiT（32.8 GB）在 4.14–7.64 s 流入，藏在 encoder 的工作下面。7.64 s 构建 DiT 对象，7.71 s 第一个 DiT step 开始。

MiniMax H3 FL2VA

  • 0.10 s 原生代码启动：启动执行器立刻校验 plan bundle。
  • DiT 和 Qwen 两个原生进程在 0.17 s 和 0.29 s 开始读，各有自己的 reader 和 CUDA context；文件预读同时为两者提前读取。
  • 请求结构的 CPU 部分在 0.10–0.53 s 运行，不等权重。
  • DiT（43.2 GB）在 6.72 s 就位，6.72–8.74 s 准备它的请求 layout，此时 Qwen 还在读。
  • Qwen（51.6 GB）在 10.07 s 就位；随后是文本 conditioning、汇合和 layout，10.20 s 第一个 DiT step 开始。这里是更大的 Qwen 决定了终点。

LTX 2.5 T2V

  • 0.26 s 原生代码启动。Gemma tokenizer 在 0.31–1.85 s 于 CPU 上准备，和 reader 同时进行；CUDA context 在 1.76 s 就绪。
  • 五组权重共用一个 48 reader 的池同时上传：upscaler（1.0 GB）3.17 s、VAE（1.5 GB）4.09 s、connectors（4.0 GB）4.63 s、Gemma（26.2 GB）6.71 s、DiT（38.0 GB）7.78 s 就位。
  • 文本 processor 的 attention plan 在 3.10–4.61 s 准备，同时上传继续进行。
  • 每组权重在首次使用时装进 LTX 的张量：6.71 s 装文本编码器，7.78 s 采样前一起装 DiT、VAE 和 upscaler。7.81 s 第一个 DiT step 开始。

5. 怎么看

时间 0 是容器里第一行用户代码。第一根条之前，容器导入很薄的 Python 服务层（只用标准库）并启动原生进程；这段时间就是第一根条。

load、prepare 和 CPU 工作 是框架声明的任务（DeclaredStartup），名字与代码一致。组件加载和上传来自共享的 loader。

磁盘读取把一个进程里所有 reader 的读取调用合并成一根条，中间的空隙表示那段时间没有 reader 在读。上方的曲线是按 0.1 s 分桶的读取带宽；折线是同一分桶里发往 GPU 的拷贝调用字节数。

所有条都截止在第一个 DiT step。之后仍在进行的工作（例如第一步用不到的组件加载）会标为仍在进行。

6. 复现

先运行一次示例，用多轮 cold start 把 Volume 跑热，直到中位数不再下降，然后跑一轮带 trace 的：

modal run examples/modal/wan21.py                              # once: build and prepare
modal run examples/modal/wan21.py --cold-start 10              # repeat until the median stops falling
modal run examples/modal/wan21.py --cold-start 10 --trace traces/wan
# the same for examples/modal/h3.py and examples/modal/ltx25.py;
# each container's spans land in traces/<model>/NNN/rust-<pid>.jsonl next to sample.json
由保存的 trace 生成；不保留文件路径、容器 ID 或哈希。所有内容都在本文件中。
